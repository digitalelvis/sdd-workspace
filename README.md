# AI - SDD Engine for Workspaces

An open-source CLI tool to quickly bootstrap "AI-Friendly", Spec-Driven Development (SDD) ecosystems. This tool automatically analyzes your current project's Stacks (Node.js, Next.js, React, Python, etc.) and seamlessly injects the appropriate knowledge base files, linter rules, testing pipelines, and AI instructions.

## Core Features
- **Multi-Stack Detection**: Analyzes `package.json` to automatically detect hybrid ecosystems (e.g., Node.js + Next.js + React.js) and orchestrate knowledge for all of them simultaneously.
- **SDD "Single Source of Truth"**: Vendored, fully offline integration of SDD Agent Skills (adapted from [tech-leads-club/agent-skills](https://github.com/tech-leads-club/agent-skills)). All AI instructions are centralized at `.agents/skills/`.
- **Decoupled Architecture (IDE vs Agent)**: Treats your visual IDE configs independently from your AI Brain:
  - **IDEs**: Setup workspace standards, auto-linters, settings (e.g. `vscode`, `webstorm`).
  - **Agents**: Inject prompt rules and read pointers (e.g. `cursor`, `windsurf`, `antigravity`, `copilot`, `kiro`).
- **Strict Linting Pipelines & Testing**: Injects tailored `.eslintrc.json`, `jest` frameworks, mutates package scripts (`lint`, `test`), and automatically pulls required dev-dependencies.
- **Workspace Hygiene**: Automatically configures `.gitignore` to prevent AI runtime configuration bloat while keeping the `.specs/` logic tracked.

## Suported Ecosystems

| Type | Definition | Supported Implementations |
| --- | --- | --- |
| **IDEs** | Visual editors providing the physical workspace layout, formatters, and terminal config environments. | `Cursor`, `Windsurf`, `Visual Studio Code`, `Antigravity` |
| **Stacks** | The architecture your project runs on. Multiple combinations are fully supported (e.g., node and react simultaneously). | `Node.js`, `Next.js`, `React`, `Python`, `PHP`, `Laravel`, `Vue` |
| **Agents** | The AI assistant engines configured to consume internal SDD docs from within your active workspace. | `Antigravity`, `Copilot`, `Cursor Engine`, `Windsurf Engine`, `Kiro` |

## The Spec-Driven Development (SDD) Workflow
By default, the master orchestrator (`tlc-spec-driven/SKILL.md`) forces all AI agents to transition into spec-driven planning mode **before** writing code. 
Any new feature logic generated by your LLM will be evaluated structurally against:
1. Identifying if the task is a new feature or story.
2. Generating a `spec.md` and `tasks.md` plan.
3. Automatically consulting Stack-specific skills (e.g., `nextjs-best-practices`) inside `.agents/skills/[stack]`.

## Usage
Run the CLI in your existing or newly created project directory:

```bash
npx ai-sdd-workspace init
```

### Advanced CLI Arguments
You can bypass the interactive prompt by explicitly stating your IDE environments and AI execution agents:

| Argument | Description | Values |
| --- | --- | --- |
| `--ide` | Defines the local visual development environment you are using. This installs standard linters and sets up paths like `.vscode` configs if necessary. | `vscode`, `cursor`, `windsurf` |
| `--agents` | Defines the specific AI brains (agents) you want initialized with SDD instructions. Accepts a comma-separated list. | `antigravity`, `cursor`, `windsurf`, `copilot`, `kiro` |
| `--no-lint` | Bypasses the auto-injection of Prettier and ESLint standard rule files. | `boolean` |

```bash
# Example: Using VS Code as the host IDE, but utilizing Antigravity and Copilot as the AI "Brains"
npx ai-sdd-workspace init --ide vscode --agents antigravity,copilot

# Example: Using Cursor (which acts as both the IDE host and the AI Agent native ruleset)
npx ai-sdd-workspace init --ide cursor --agents cursor
```

If you do NOT want the CLI to enforce strict linting parameters, you can opt-out:
```bash
npx ai-sdd-workspace init --no-lint
```

## Extending Frameworks and IDEs
Developers or AI Agents seeking to push new structural schemas inside this engine MUST look into `/src/scaffolder/providers/`.
We utilize a heavily decoupled Strategy and Facade architecture for adding explicit `Stacks` and explicit `Ides`.

## Contribution & Governance
We adhere strictly to Open Source SemVer guidelines.
No direct development applies to `main`. All pull requests must branch from the active release version line (e.g. `v0.1.x`) following Conventional Commits, and you must update `/CHANGELOG.md` appropriately.

**For AI Agents:** Please read the strictly enforced instructions localized in `.agents/rules/repo-governance.md` before executing any PR tasks.
